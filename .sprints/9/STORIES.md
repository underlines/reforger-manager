## S1 — extract the coverage pipeline into `lib/modCoverage.ts`

Create `frontend/src/lib/modCoverage.ts`; refactor
`frontend/src/components/server/ModsPanel.tsx` to consume it. Two files only.

**Deliver.**

1. New module `frontend/src/lib/modCoverage.ts` exporting:
   - `export type DepNode = { guid: string; name: string | null; via: string; state: string; depth: number };`
   - `export type ModDeps = { dependency_tree: { nodes: DepNode[] } | null };`
   - `export function useModCoverage<T extends { mod_guid: string }>(items: T[]): { coverageByParent: Map<string, ReadonlySet<string>>; covered: ReadonlySet<string> }`
     — move ModsPanel's `depResults` (`useQueries`, key `["mod", mod_guid,
     "deps"]`, queryFn `api<ModDeps>(\`/api/mods/${mod.mod_guid}\`)`,
     `staleTime: 60_000`), `depSig`, `depEdges`, `coverageByParent` and
     `covered` memos here **verbatim** (same key construction, same
     `depth > 0 && state !== "unresolved"` filter, same `seen`-set stack
     walk excluding the parent, same
     `// eslint-disable-next-line react-hooks/exhaustive-deps` pragmas where
     they were needed). `coverageByParent` maps each item guid to the set of
     OTHER item guids reachable through its dependency closure; `covered` is
     their union. While an item's deps query is still loading its edge set is
     `undefined` → that item covers nothing (same as today).
2. In `ModsPanel.tsx`: delete the local `DepNode`/`ModDeps` type declarations
   (`:34-35`) and the `depResults`/`depSig`/`depEdges`/`coverageByParent`/
   `covered` block (`:268-334`); replace with
   `const { coverageByParent, covered } = useModCoverage(working);`. Import
   `DepNode`/`ModDeps` for the remaining local uses (`AddModRow`, the deps
   `useQuery` inside `AssignedModExpanded`) from the new module. Everything
   else — `topLevel`, `reorderVisible`, `expandedRows`, `AssignedModExpanded`
   (its own `useQuery` for `["mod", parent.mod_guid, "deps"]`), `AddModRow` —
   stays untouched. `EMPTY_GUIDS` stays in ModsPanel.

**Done when.** `cd frontend && npm run build` clean; the Mods tab renders and
behaves identically (hidden covered picks, ▸ disclosure, drag splice-back);
`git grep -n "DepNode" frontend/src` shows the type only in `lib/modCoverage.ts`
and its importers.

**Watch out.**
- `useQueries` ordering matches `items` index-by-index — the moved hook must
  key its queries off the same `items` array the caller renders from.
- Keep the `depSig`-style signature (`result.dataUpdatedAt`/`status` join) so
  the memos don't recompute on unrelated renders.
- This is a pure move + rename of the plumbing, **not** a behavior change —
  if you find yourself "improving" the walk, stop.

## S2 — Modpacks editor: explicit picks only + dependency-aware view

`frontend/src/pages/Modpacks.tsx` only (plus imports from S1's module).

**Deliver.**

1. **Add path** — replace `addItem` (`:139-168`) with a synchronous add of
   the explicit pick only (dedup against current `items` via a `Set`; no
   `fetchQuery`, no dep nodes). Drop the `useMemo`-free async plumbing and the
   local `DepNode`/`ModDeps` types (`:18-19`) — import them from
   `lib/modCoverage.ts` if still referenced (S3 note: they won't be, except
   via the hook). `EditorItem` (`:16`) is unchanged.
2. **Coverage wiring** — `const { coverageByParent, covered } =
   useModCoverage(items);` then:
   - `topLevel = useMemo(() => items.filter((item) => !covered.has(item.mod_guid)), [items, covered]);`
   - `reorderVisible(nextVisible)`: splice-back exactly like
     ModsPanel `:345-352` — map over `items`, covered rows pass through,
     others shift from `nextVisible` in order.
   - `expandedRows: Set<string>` state + `toggleExpanded` (ModsPanel
     `:355-362` pattern). Reset it in `openCreate`/`openEdit` is optional;
     default closed is fine.
3. **Render** — in the Pack-contents `<section>` (`:366-389`):
   - Pass `items={topLevel}` and `onReorder={reorderVisible}` to
     `SortableModList`; keep the count header as `items.length` (stored
     count — PLAN decision 5) and the existing remove-button `renderActions`
     on top-level rows.
   - Add to `renderActions` a ▸/▾ disclosure button (ModsPanel `:767-775`
     shape: `size="sm" variant="ghost"`, `aria-expanded`, `aria-label`
     "Show/Hide dependencies") toggling `expandedRows`.
   - Add `renderExpanded={(item) => expandedRows.has(item.mod_guid) ? (
     <PackItemExpanded parent={item} items={items}
     coverageGuids={coverageByParent.get(item.mod_guid) ?? EMPTY}
     onRemove={removeItem} />) : null}` where a new local component
     `PackItemExpanded` (modeled on `AssignedModExpanded` `:1174-1298`,
     minus enable/pin) renders, inside the existing expanded-subtree classes
     (`border-l-2 border-stone-800 pl-3 text-[11px] text-stone-400`):
     - **covered picks first**: every `items` row whose guid is in
       `coverageGuids` — `<Link to={\`/mods/${row.mod_guid}\`}>` name,
       a `<Badge tone="neutral">pick</Badge>`, and a small
       **Remove** button calling `onRemove(row.mod_guid)` (it is stored; the
       user may not know why it is here — the badge + Remove is the whole UI).
     - **then pure dep nodes**: its own `useQuery` keyed
       `["mod", parent.mod_guid, "deps"]` (shares the cache with the hook and
       every other consumer); nodes with `depth > 0` and guid **not** in the
       pack (`!items.some(...)` — or a `Set` built from `items`) sorted by
       depth then name; resolved → `<Link>` + `via {node.via}`; `unresolved`
       → guid + `<Badge tone="warn">unresolved</Badge>`, no link
       (`stopPropagation` on every Link click).
     - loading → `...`, error → small error line, "no deps & no picks" →
       `No dependencies.` — same branches as `AssignedModExpanded:1264-1295`.
4. **Save** — no change: `save` already maps `items` order to `load_order`
   (`:177`); splice-back guarantees covered rows keep slots.

**Done when.** `npm run build` clean. Manual (PLAN "Testing" cases 1-5): add a
mod with deps → only the pick is stored and listed; its ▸ shows read-only dep
links; a second pick that is also a dep hides under the first with a `pick`
badge + Remove; removing the parent resurfaces it; drags persist with covered
slots intact.

**Watch out.**
- `renderActions`/`renderExpanded` run for top-level rows only — a covered
  row's Remove must live in `PackItemExpanded`, not in `renderActions`.
- `coverageByParent.get(...)` may be a `Set` that includes guids **not** in
  `items` in theory? No — the hook only reaches explicit picks; but the
  lookup can be `undefined` while loading → default to an empty stable set
  (`EMPTY_GUIDS` pattern, PLAN shared-reference table).
- Don't touch the apply/export/import/delete dialogs or the "Add mods from
  the library" picker section (`:391-435`) beyond `addItem` itself.
- The `key` on dep-node rows in the expanded list is
  `${node.guid}-${node.depth}` (same GUID can appear at two depths) — copy
  `AssignedModExpanded`.
- `covered` shrinks when a parent is removed → `topLevel` recomputes → the
  resurfaced row needs its `EditorItem` fields intact. It never left
  `items`, so it does.
